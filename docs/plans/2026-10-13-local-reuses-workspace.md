## Design

### Modes

`Workspace` = `Isolated` | `Fork` | `InPlace`, resolved once in preflight and recorded on the run.

- Resolution: machine.toml `[workspace] mode = "auto" | "isolated"` (absent file/key = `auto`). `CI` set, or `RELAIS_WORKSPACE=isolated`, forces `isolated`. A repo's `relais.toml` can only narrow: `[workspace] in_place = false`. Precedence, stated once: `--workspace` > `RELAIS_WORKSPACE` > `CI` (non-empty and not `0`/`false`) > machine.toml > `auto`; an env or CI `isolated` cannot be widened by the flag (block, exit 3); an unknown value exits 2.
- `auto`: cwd root is a **linked worktree** (`git rev-parse --git-dir` ≠ `--git-common-dir`, both absolute; new `repo::is_linked_worktree`) → `InPlace`; otherwise → `Fork`.
- Explicit override `relais run --workspace auto|fork|in-place|isolated` (plugin tool param). `in-place` on a primary checkout → block `in_place_refused_primary`, nothing launched (never silently downgraded). `auto` on a primary checkout simply forks.
- `Isolated` runs the existing code path with zero edits to it: the new behaviour lives in a new module `workspace/reuse.rs` and is entered only through one `match` in `runner/mod.rs` at the three tree-creation sites.

### Fork + copy-on-write deps, and what setup may be skipped

Two separate things. **Seeding** copies dependency directories copy-on-write; it is always safe because every setup step still runs afterwards. **Skipping** a setup step is allowed only for a step that declares how its result is identified and checked, and defaults to never.

1. Which dirs are seeded: `relais.toml` `[workspace] deps = ["node_modules", "target"]` (relative paths, any depth), else detected: top-level and one-level-nested (`packages/*/node_modules`) dirs named `node_modules` or `target`. **`.venv`/`venv` and any directory holding `pyvenv.cfg` are never seeded** (embedded absolute interpreter paths; Python documents environments as non-portable): rejected at parse when declared, skipped when detected, until a relocation-aware implementation exists. **Safety:** every candidate must be git-ignored (`git check-ignore -q`), relative, free of `..`, not under `.git`, not tracked.
2. Clone, never copy: macOS `clonefile(2)` with `CLONE_NOFOLLOW`; Linux `FICLONE` per regular file (walk), modes/mtimes preserved, hardlinks cloned as separate files. New `fsclone.rs`, `libc` calls under `#[cfg(target_os)]` like `procs.rs`. **Symlinks** are resolved lexically against the destination: a relative link that stays inside the repository root is kept (yarn workspace links `../../packages/x` then point at the destination's own packages); an absolute target, or a target that resolves into the source workspace or outside the repository root, aborts the seed (fallback). A **probe** first clones a 1-byte temp file source-volume→destination-volume. `EXDEV`/`ENOTSUP`/`EOPNOTSUPP` → event `workspace_cow_unavailable` (reason, both volumes, and the fix `put RELAIS_STATE_DIR on the source's volume`, in the `workspace_resolved` pane event and receipt notes) and today's behaviour. A clone that fails halfway removes the partial destination; it never falls back to a byte copy.
3. Source = the caller's workspace (cwd root). Seed the task tree before setup; seed `verify-base` and candidate trees from the task tree.
4. **Default: every setup step runs, in every tree, as today.** On a seeded tree a matching install is usually a no-op in seconds (Yarn/npm/cargo check themselves), and `ensureWorkspacePackagesBuilt` or `postinstall:real` do their own freshness checks; this alone removes the 10–25 min install and the 6.5 GB. Nothing is skipped by key, lockfile or mtime.
5. **Opt-in skip, per step.** A setup step may declare `reuse = { inputs = [globs], outputs = [paths], verify = [argv] }` (`#[serde(default, skip_serializing_if)]`, so existing policies and hashes do not move; once set it is part of the authority hash and of the `commands_changed` step line). Relais skips that step in a seeded tree iff all hold: (a) the step's key equals the key stored for the source: sha256 of {step argv, content hashes of every file matching `inputs` (manifests, lockfiles, patches, package-manager config, the step's own script, and for a build step the sources it compiles), the toolchain of `argv[0]`, and the keys of all earlier setup steps}; (b) every declared `outputs` path exists and is non-empty in the seeded tree (a build's `dist/`, `node_modules`); (c) `verify` exits 0 in the seeded tree (for Yarn 1: `yarn check --integrity`; for a build: a one-line import check). Any miss → the step runs. A step with no `reuse` is never skipped, and a step declaring `outputs` that are not git-ignored is rejected at parse. Mtimes and entry counts have **no** authority here (a timestamp-preserving rewrite defeats them); they only decide when it is polite to clone (see failure cases).
6. The key is stored in `<state>/workspace-stamps/<sha256(canonical path)>.json` after any successful run of that step in a tree relais populated. No stamp (a hand-installed tree like happier-wt-n1's) → seed, run the step. Skipped steps record `workspace_setup_skipped {step, key, source}`: evidence, never a check (SPEC §10: a setup that succeeded passed nothing).
7. Trees never share writable state: a clone is COW; the source is only read.
8. happier gets reuse only where it is cheap to state: the `yarn install` step (inputs, matched against tracked files only (`git ls-files`): `yarn.lock`, `**/package.json`, `.yarnrc*`, `patches/**`; outputs `node_modules`; verify `yarn check --integrity`). The patch step and `ensureWorkspacePackagesBuilt` keep running; if the pilot shows the build step is slow, its `reuse` (inputs = its script + `packages/**/src/**`, outputs = the workspace `dist/` dirs, verify = a workspace-package import) is added later with its own test.

### In-place

- Applies to the task worktree only: no `git worktree add`. Setup steps run in place by the same rule as everywhere (every step, unless it declares `reuse` and all its conditions hold in this tree).
- **Start snapshot `S`.** If the tree is clean, `S` = `HEAD`. If dirty (accepted by decision), `S` = a synthetic commit (parent `HEAD`, fixed author/date like `snapshot_candidate`) of tracked + untracked-not-ignored files, built with a **temporary index** (`GIT_INDEX_FILE=<git-dir>/relais-inplace/<run>.index`, removed on drop, exported to the worker and setup, scrubbed from every other child) so relais never stages or resets the person's real index; kept at `refs/relais/starts/<run>` so uncommitted work stays recoverable. `S` is used everywhere `base_sha` is today: scope check, candidate diff, `snapshot_candidate` parent, verify-base tree, patches. `TaskWorktree` gains an optional index file: in-place, every index-touching git call (`snapshot_candidate`'s `add -A`/`write-tree`, `workspace/mod.rs:315-316`; `changed_paths`' `ls-files --others`, `:294`; retire's export) runs with `GIT_INDEX_FILE` = a temp index seeded by `read-tree S`; isolated passes none, so the person's real index is never staged. **The worker and setup steps run with a separate throwaway `GIT_INDEX_FILE`** (`<run>.worker.index`), so their `git add`/`git status` act on it and not on the person's. Relais never reads it: its own calls use a private `<run>.relais.index`, re-seeded by `read-tree S` before every snapshot, so a worker's `--skip-worktree`, or a foreign repo's `git` writing through the inherited variable, cannot alter a candidate. This is containment, not a sandbox (SPEC §8: Bash is not confined): relais also copies the real index to `<git-dir>/relais-inplace/<run>.index.orig` at start and records its sha256; if the real index's `git ls-files -s` output differs at the end (a worker that unset the variable, or used `--git-dir`), the receipt notes `real_index_changed`, the original copy is kept, and `resume --retire` offers it back. Relais promises detection and recovery evidence, never byte-identity against an adversarial worker. `HEAD` (symbolic ref + SHA) is recorded at start; in-place trees sit on the person's branch (isolated ones are `--detach`), so a worker `git commit` moves it: if `HEAD` moved by the end the run blocks `inplace_head_moved`, exports unkept work to `…/final`, and leaves both the tree and the branch exactly as they are (no restore to `S`, never a reset). The receipt and report list `start_dirty_paths`: "base included uncommitted work", so a reviewer is never misled.
- **Lock.** One fixed lease file per worktree `<git-dir>/relais-inplace.lock` (git-dir of the linked worktree, so it never shows in `git status`), taken with `procs::LockFile::try_acquire` (`Ok(None)` = busy, atomic) and held for the run's life (kernel releases it on any death), holder run id written inside. A per-run marker `<git-dir>/relais-inplace/<run>.json` is removed at a clean end: a marker present while the lock is free = an interrupted run. Another run in the same worktree while the lock is held → block `workspace_busy` naming the run. v1 runs **sequentially** in a worktree: run B may start dirty with run A's applied edits (this is the orchestrator-sliced case). Concurrent runs with disjoint write scopes are **not** in v1: B's base would contain A's half-written edits (see Not in scope).
- Start message (plugin, `runs.ts:207`) names only the requested mode: `Started relais run for <task> in <cwd> (workspace: <requested>). It runs in the relais pane …`; the plugin returns before preflight and cannot know the resolved mode. The run's first protocol event `workspace_resolved {mode, path, lease, cow}` renders in the pane and outcome; for in-place it reads `in place in <cwd>: do not edit it until the outcome arrives (lease held)`. The lock is advisory against the person; an edit outside the contract's scope shows up as a scope violation.
- **End, with a persisted decision.** Never `worktree remove`. Before touching the tree the runner writes (atomic, fsynced) into the per-run marker `<git-dir>/relais-inplace/<run>.json` the **finalization**: `{state: finalizing, target: {kind: accepted|start, tree: <sha>}, head_symbolic, head_sha}`, where the target is the accepted candidate's tree (`Accepted`/`accepted_by_person`) or `S`'s tree (every other terminal). Then it exports whatever no candidate holds to `…/final` (retire's step (a), extracted as `export_unkept`), records `exported: <ref>` in the marker (a resume skips the export when present, so a half-restored tree never overwrites `final`), applies the target, and removes the marker last. Applying a target is **idempotent**: it diffs the current tree against the target tree and converges, so a rerun after a crash at any point completes it.
- **Applying a target (`reuse::apply_tree`).** No `checkout-index -a -f`. (1) Preflight, mutating nothing: list `git diff-tree -r -z --no-renames <current> <target>` plus untracked-not-ignored paths; for every path whose type changes (file↔directory, symlink↔either) check whether the existing directory holds ignored descendants (`git ls-files -o -i --exclude-standard` under it) or untracked-not-ignored content not in the end snapshot. Any such collision blocks with `restore_blocked_ignored_collision`, listing the paths, mutating nothing; the exported `final` already holds the tracked work and the person decides. (2) Deletions in post-order (files and symlinks first, never following a symlink, then directories only if empty). (3) Creations and modifications in pre-order (directories before their children), each written with `git checkout-index -f -- <path>` against an index loaded by `read-tree <target>` (`<current>` = a fresh `add -A` snapshot tree in the private index), symlinks via `unlink`+`symlink`. Ignored files outside collisions are never touched. The real index is untouched.
- **Recovery** (`relais resume --retire <run>` only; the next run's preflight blocks `workspace_has_interrupted_run` and recovers nothing): take the same worktree lock; recheck `HEAD` against the recorded value (moved → `inplace_head_moved`, tree and branch left alone) and that no live writer or unproven dispatch remains (the check `retire_worktree` already makes for `Keep`); then, if the marker says `finalizing`, resume to its recorded target; if it says only `running` (the process died before deciding), read the ledger: a recorded `Accepted` with a candidate ref → target = that candidate, else target = `S`. The marker is removed only after the target is applied and verified equal (tree hash of a temp-index snapshot). A second `resume --retire` on a finished run finds no marker and does nothing.
- Verification: base tree `verify-base` at `S` and candidate trees stay separate `git worktree add --detach` checkouts, CoW-seeded from the in-place tree. §10's "immutable copy of the candidate" holds unchanged.
- Coordinator write lease keyed by the **canonical** path (the key is a raw string today) so differing spellings collide.

### Base verdict reuse

- Key moves from base SHA to the base **tree hash** (`rev-parse S^{tree}`) + existing profile/tool/toolchain parts. Setup identity is the whole `setup` step list (argv and any `reuse` declaration), already inside the profile hash; no lockfile subset is added. A synthetic start commit and a real commit with the same tree share a verdict. Bump `BASELINE_MEANING_VERSION` to 3 (old entries miss, never misread).
- Cache also the check outcomes (not only failed labels) so a hit keeps the identical-candidate shortcut that a hit loses today.
- Still opt-in (`cache_baseline = true`, SPEC §18: only for profiles with no undeclared external dependency). The happier profile turns it on. A base verified in a seeded tree writes the cache only if every setup step ran to success in it (the default), and **not** when any step was skipped by `reuse` from a source whose key differs from this tree's.
- `CacheRefused` reasons unchanged.

### Trust and authority

- Mode and `in_place` opt-out are about *where* declared commands run, not *which*. The repo grant already covers the repository; in-place is only reachable in a linked worktree of that same repository (identity from `repo::identity`), and the person can always force `isolated` machine-side. A committer cannot widen it: relais.toml can only turn in-place **off**.
- `[workspace]` and a step's `reuse` are `#[serde(default, skip_serializing_if = …)]`, so `authority_hash` of every existing policy and the `the_authority_hash_survives…` pins do not move; a new test pins a policy that sets them. `deps` and `outputs` are validated at parse. `[workspace]` (data only) is not in `trust::declaration`; a step's `reuse` **is** added to that step's line, because it changes whether a declared command runs, so `commands_changed` warns when it appears or changes. The stale doc on `Declaration` (`trust.rs:71-75`) is corrected in passing.
- machine.toml `[workspace]` is a new table; a v0.19 binary cannot read it (`deny_unknown_fields`). Absent by default, so only a person who sets `mode = "isolated"` hits this; rollback = delete the table. Stated in CHANGELOG.
- Replay (SPEC §24) and live trials keep their fresh single-commit checkout: they force `Isolated`.

## Failure cases

| Case | Handling |
|---|---|
| Clone source is mid-install | Best-effort politeness, **not** identity: before cloning, wait while the source's dep tree still changes (recursive newest-mtime and entry count unchanged over 30 s, skipped when a relais-written stamp is over 30 s old and still matches) and no `installing` lock is held (a `procs::LockFile` in the stamp dir that relais holds while it runs setup in a tree it owns). Poll up to 60 s, emitting `workspace_seed_waiting {source, waited_s}` every 10 s, then seed nothing (`workspace_seed_skipped: source busy`) and run today's full setup. The heuristic can be fooled (timestamp-preserving writes, a future-dated file), so it never authorizes anything: a half-written or mutated seed is caught because every setup step runs afterwards, and a `reuse` skip additionally needs its own `outputs` and `verify` to pass in the seeded tree. |
| Lockfile or manifest differs, caller vs base | Seed anyway and run every step (incremental install reconciles); any `reuse` skip is refused because its key differs. Receipt notes `deps_seeded_from_different_inputs`. |
| Caller is the primary checkout | `auto` → Fork (CoW). Explicit `--workspace in-place` → `in_place_refused_primary`, exit like other blocks, zero launches. |
| Two runs in one worktree | Second blocks `workspace_busy` (live lease). Sequential runs are fine; the second starts dirty and its `S` includes the first's applied edits. |
| Run killed mid-way in-place | Kernel drops the lock. The tree holds partial edits and nothing is auto-restored. The run is `interrupted`. A new run in that worktree blocks `workspace_has_interrupted_run <run>` until `relais resume --retire <run>`, which follows **Recovery** above (export, then the persisted target, never removing the directory); the block names that exact command. Dirty acceptance does not hide this: the check reads the leftover marker `<git-dir>/relais-inplace/<run>.json` while the lock is free. A crash after `Accepted` is recorded but before the marker names a target still recovers to the accepted candidate, from the ledger. |
| Filesystem has no CoW / different volume | Probe fails → named event and message, today's full setup. Never a silent byte copy. |
| Restore would clobber ignored files | A path-type change (file↔directory) over a directory with ignored or unknown content is found in the preflight and blocks `restore_blocked_ignored_collision`; nothing is deleted. |
| Worker stages or commits | Staging goes to the temp index (the worker has `GIT_INDEX_FILE`); a commit moves `HEAD` → `inplace_head_moved`; a worker that bypasses the variable changes the real index → `real_index_changed` + the kept `.index.orig`. |
| Worker destroys the tree | `S` is a commit under `refs/relais/starts/<run>`; tracked and untracked-not-ignored work is recoverable. Ignored files are not (same as any worker today). |
| Person edits during an in-place run | Advisory lock + start message. Edits outside scope → scope violation; inside scope → indistinguishable from the worker's, called out in the message. |

## Verification

Acceptance (each a command; `make check` must exit 0 first):

1. **Disk bound.** `cargo test -p relais workspace_seed_bound`: fixture with 256 MiB `node_modules` (64 × 4 MiB random files); run `seed_deps`; assert every file was cloned by the syscall (count returned by `fsclone`) and, on Linux, that FIEMAP reports `FIEMAP_EXTENT_SHARED` on a sample, with a reflink loop-mount variant (btrfs/XFS) so the CoW path runs in CI. The `statvfs` free-space delta (≤ 8 MiB + 2 %) is an `#[ignore]`d check on a private APFS `hdiutil` image or reflink loop mount, since free space is volume-wide and parallel builds make it noisy. On a filesystem without CoW the same test asserts `workspace_cow_unavailable` and that nothing was copied. Manual on the real case with a scratch state dir: `df` before/after a run in `happier-wt-n1`.
2. **Setup skip.** Runner tests in the style of `:9863` (flag-file setup). A step with no `reuse` always runs. A step with `reuse`: all conditions hold → `task-setup<n>.log` absent and `workspace_setup_skipped` recorded; each of unchanged lockfile + changed `package.json`, changed patch file, changed setup-script content, changed package-manager config, changed argv, changed toolchain, a changed earlier step → runs; a declared `outputs` path missing from the source (a build's `dist/`) → runs; `verify` failing → runs; a timestamp-preserving rewrite of one dep file (same count, same max mtime) passes the quietness heuristic but the always-running steps or `verify` catch it (a corrupt-seed test asserts the step runs and repairs it). A `reuse` whose `outputs` are tracked → parse error. **happier pilot:** in a fresh seeded checkout, import every internal workspace package (`node -e "require.resolve(...)"` for each) and run the first lane of `yarn verify`.
3. **In-place refuses the primary.** CLI integration test: `relais run --workspace in-place` in a primary checkout → `in_place_refused_primary`, no worker; same task in a linked worktree → runs, edits land in the worktree, patch = diff vs `S`.
4. **Server unchanged.** `RELAIS_WORKSPACE=isolated` and `CI=1` each: a golden fixture of the run's events, log names, `state/worktrees` + `state/verify` layout and ledger rows (ids/timestamps normalised) generated from the **v0.19.0** binary before the change, asserted equal after; the isolated path is pinned by this fixture, not by diff shape (in-place end handling and skip-setup also land in `runner/mod.rs`). ## Not in scope

- Concurrent runs in one worktree with disjoint scopes: B's start snapshot would contain A's half-written edits, so B's base verdict and patch would be contaminated. Needs per-scope base reconstruction; its own plan.
- Sharing one install across runs by hardlink/symlink (not CoW-safe for tools that write into `node_modules`).
- Server/CI mode itself; only the default-off switch exists.
- A `relais apply` command; the exported candidate/patch remains the integration route.
