# relais learns from what it routes: spawn exploration, replay observations, a floor read off a curve, and Laya in its place

## Review panel

👉 **Decide:** none — approve if exploring subagent spawns, keeping replays as arm observations, and a floor sweep reported beside the gate are how relais gets data worth learning from.
📍 relais · Phases 1–4 built and verified on a scratch ledger, v0.16.0 commit on the branch · next: PR, release, plugin reinstall, then the live rows (day 14: 2026-10-25). Panel: backend (opus-5-5), lang:rust (opus-5-5), tui (opus-5-5), unix (opus-5-5).
**Changed by review:** the three known replays predate ledger v17 and stay excluded (sources restored, replay = 0 until a new replay); the gate's `test_records`/`abstention_rate` count tasks, stated as a unit change; a drawn spawn never lands on an excluded model, and the strata join carries no `agent_id` filter.
📄 Full reviews: [2026-10-11-learning-faucet.reviews.md](2026-10-11-learning-faucet.reviews.md)
**Verdicts:** round 1: 4 approve-with-changes (2 high, 1 duplicate); round 2 backend approve-with-changes (1 high applied), binding run approve; 6 findings carried into implementation.

## Context

The learning loop shipped in v0.12.0 (plan `2026-10-10-learning-loop.md`) and the first live cycle ran on 2026-10-11 02:10. It trained nothing promotable, as expected. The question that prompted this plan was whether Laya is used enough and where it belongs, and whether `microsoft/best-route-llm` has logic worth salvaging. The live ledger and the code answer both, and the answer is upstream of Laya:

- **Exploration barely draws.** It went live on 2026-10-11 (the first `router_decisions` rows with a propensity are that day's). Draws happen only on main-session `new_task` starts (`claude-plugin/hooks/router.ts:644`, `exploreAt`): 29 eligible decisions on day one, 1 explored. Subagent spawns are where the router actually switches models (113 of 130 spawn decisions since 10-08 were applied; 579 of 772 routed decisions went to the escalation tier because a new task is raised to the session's own tier, `router.ts:639-641`) and implementation spawns run their own checks, yet `decideSpawn` (`router.ts:1002`) never draws and the strata query (`crates/relais/src/ledger/router.rs:696-727`) excludes every subagent task (`d.agent_id = '' AND d.relation = 'new_task'`). The biggest main-session stratum, questions at difficulty 1–2, mostly ends `unknown`, so the stop rule's "20 drawn tasks with strong outcomes" has no projected date.
- **Replays destroy the example they were run for.** `dataset::build` (`crates/relais/src/learn/dataset.rs:338`) keeps the newest root run per task (`:357-368`, "superseded by a later attempt") and never reads `runs.purpose`. A `dataset replay` run shares its source task's id (`main.rs:5585-5586`, `purpose: Replay`), so it supersedes the accepted source run. Verified on the live dataset `20261011T021000.json`: the three replayed tasks (`task-d3b46f3fbe9369a6`, `task-cacd81caef38bc09`, `task-fe69de8bb089e0f6`) have zero records; their source runs read "superseded by a later attempt" and the replay runs are absent too. The one mechanism that produces a counterfactual (the same task on a cheaper arm, SPEC §24) currently subtracts from the dataset.
- **The quality floor is a constant nobody has measured.** `select_learned` (`crates/relais/src/route/mod.rs:782`) takes the cheapest arm whose predicted acceptance clears `[routing] quality_floor` (`policy/mod.rs:1368`, 0.75 by default), and `evaluate` gates on the same number. Nothing reports what the test split looks like at other floors, so the floor cannot be chosen from evidence and a flat curve (nothing to learn) is invisible.
- **Laya runs nowhere today.** Three plans reserve jobs for it, all data-gated: distil the haiku classifier (learning-loop Phases 6–7, 2,500 parsed calls; 162 today at about 173 a day), "does this tier succeed" (Phase 8, 20 drawn tasks in a stratum), and the approve advisor (orchestrator-decides Phase 4, 200 person answers; about 100 today). The classifier job buys the least: haiku costs about a tenth of a cent a call and answers in 1.5–1.7 s; the Laya model card gives 193–464 ms per request preloaded but 7.4 s to load cold on CPU, so a process-per-call advisor (orchestrator-decides 4b) is right for a few decisions a day and wrong for 173 prompt-path calls a day. The advisor is the best fit (typed JSON state, one yes/no, one forward pass), with two details from the model card the plan must carry: the per-question probability, never the `act_probability` head ("carries no usable signal yet"), and a fitted temperature (the checkpoints ship over-confident, ECE 0.47 before refit).
- **best-route-llm.** About 1,900 lines of Hugging Face Trainer glue around DeBERTa-v3-small, MIT; `bubble` inference is declared and unimplemented; the selection lives in a notebook; labels are chatbot prompts scored by a reward model. SPEC §16's rule for RouteLLM applies: nothing to import. Its two ideas relais lacks are counterfactual arm observations (their soft label is `P(quality(cheap) ≥ quality(strong) − t)` over sampled pairs) and a threshold swept into a cost/quality curve. Both land here, in Rust, on relais's own verified outcomes.

**Intended outcome:** exploration draws at the volume the router actually routes; a replay adds an arm observation to the dataset instead of removing one; `relais report` shows what the test split looks like across floors and how many accepted tasks have no cheaper-arm observation; the two Laya plans say what the model card and the live numbers changed; and on day 14 (2026-10-25) the person reads a projected date for the busiest stratum instead of `no projection`.

## Phase 1: exploration draws for subagent spawns (plugin + Rust) — done

**1a, structural (plugin).** `exploreAt` (`router.ts:669-678`) becomes a thin caller of an exported `drawAt(state, session, taskId, tier): Exploration | undefined` with the same guard line (`mode !== 'on' || holdout || !(epsilon > 0) || !seed || !session`), the research case (`explored: false, propensity: 1`) and the draw. No behaviour change.

**1b, behavioural.**
- **Key.** `routeSpawn` (`claude-plugin/hooks/routing.ts:367-392`) mints `spawnTaskId = task-${now}-${++r.seq}` *before* `decideSpawn` and passes it to `afterSpawn`, which passes it to `newTask` instead of minting at `:415`. The draw key stays (seed, session, task id), the one the shared test vector in `docs/router-protocol.md` defines; keying on `seq` alone would not be recomputable from the ledger.
- **Draw.** `decideSpawn` gains `session` and `taskId`. It draws only on its final `table` branch (`router.ts:~1032`), through `drawAt`: never for a pin, a person-named model, an abstention, a spawn whose lowered model is in `excluded_models`, or outside mode `on` / inside the hold-out (the same conditions as `isApplying`, `routing.ts:73`). Explored: `tier = stepDown(table)` with that tier's model and effort; when `stepDown(table)`'s model is in `excluded_models` the draw is skipped (no propensity recorded), with a test *a spawn whose lowered model is excluded never draws*; at research `explored: false, propensity: 1`. `wouldPassGate` stays `true` (a new subagent has no cache).
- **Floor.** `afterSpawn` sets `task.exploredDown = !!spawn.decision.exploration?.explored` (`newTask` sets it false at `router.ts:527`); without it the subagent's `rerun` on `scope_growth` (`:965` → `floorTier` `:375-377`) would raise it straight back. `escalate` (`:689`) is unchanged, so recovery still applies and its cost counts against the drawn arm.
- **Wire.** Nothing new: `decisionRecord` (`router.ts:1077-1079`) already serialises `explored`, `propensity`, `draw`; the `router_decisions` columns exist.
- **Strata (Rust).** `ExplorationTask` (`ledger/router.rs:190`) gains `relation` (`new_task` | `subagent`). `router_exploration_tasks` becomes a UNION: the existing main arm, plus a subagent arm joined on `(session, task_id)` only with `d.relation = 'subagent'`, with no `agent_id` condition on either side. An unkeyed spawn's decision row carries `agent_id = ''` (`routing.ts:430`, `agentId ?? null`) while its task row may later carry the real id (`:326`), and a spawn that never keys keeps `''`, so any `agent_id` filter would drop drawn tasks from the stop rule. `router/explore.rs:71` keys strata by `(relation, kind, band, scope)`; labels are prefixed `main`/`sub`, with a one-line legend under the table (`sub = subagent spawn`); `stop_check` (`:133`) is unchanged in code and stays one rule over every stratum with draws, so a stop fired by spawn strata also ends main-session draws (accepted: the stop is a safety rule, and there is one `epsilon`). `router/report.rs` `StratumRow` gains `relation`; the top-5 cap is shared, then `+N more`; rows stay within 80 columns; a stratum with fewer than 20 drawn tasks reads `no projection: N of 20 drawn tasks`, so the person on 2026-10-25 sees how far it is.
- **Rate.** One `epsilon`, under the 0.1 `epsilon_max` envelope in machine.toml. No spawn-specific rate.
- **Docs.** `docs/router-protocol.md:66-68,76,78` and `docs/SPEC.md:994`: "At a main-session `new_task` start, and at a table-routed subagent spawn…"; drop "subagents" from the never-explored list; name the spawn key and the never-drawn cases; add the `relation` dimension. The SPEC edit is the product statement of D1; it is not the Laya text D2 excludes from SPEC.
- **Tests.** `claude-plugin/tests/router.test.ts:397-427`: the spawn assertion at `~412` moves into a new test *a table-routed spawn draws with its own task id; pins, person models, abstentions, excluded models, held-out and shadow spawns never draw*; *a drawn spawn starts one tier lower and its rerun keeps that floor* (`decideSpawn` → `newTask` with `exploredDown` → `rerun(…,'scope_growth')` never rises above `stepDown(table)`); *a research spawn records propensity 1 and explored false*; a routing test *the spawn's decision record and its subagent task share the pre-allocated id*. Rust: `crates/relais/tests/session_router.rs:619-707` gains *subagent draws reach the strata and the stop rule* with keyed and unkeyed spawns; `explore.rs` gains *main and subagent draws are separate strata*; `router/report.rs:566-640` gains *strata rows name their relation and stay within 80 columns* using the longest kind, `d4-5`, `cross-cutting`.

## Phase 2: a replay run is an arm observation, not a later attempt (Rust, `learn/dataset.rs`) — done

**2a, structural.** `TrainingExample` (`learn/features.rs:404`) gains `#[serde(default)] origin: Origin` (`Live` default | `Replay`, `as_str`), beside `LabelSource`; the literal constructions in `features.rs`, `dataset.rs`, `evaluate.rs` are updated.

**2b, behavioural, in `build` (`dataset.rs:338`).**
- `runs_since` stays as it is (five other callers). Purpose is read per run with `Ledger::run_purpose` (`ledger/mod.rs:2988`). Live runs (purpose absent or `TrialArm`) are processed first, newest-first, one per task, as today; the chosen run id and family per task are kept.
- A `Replay` run is matched to its trial through `trials_by_task` (`ledger/mod.rs:5244`) on `arm_run_id == run`. It is excluded, with the reason named, when no trial row exists (or the row predates v17), the trial is unsettled, its outcome is `Errored` (SPEC §17: an infrastructure failure is never a reasoning failure), or its `source_run_id` is not the task's chosen live run (the replayed source was itself superseded).
- Its label is `labelling_of(state, None, None)` on the replay run's own state: the task's `latest_outcome` (revert, regression) describes the landed source patch, never the replay arm. Escalation from `escalation_attempted(replay_run)`; route from that run's own decision; tier from `run_contract_and_tier`; model, effort and harness from `first_dispatch_intent` (`ledger/mod.rs:4998`); **`recipe_id` from `trial.arm_recipe_id`**, never `covering_recipe_id(current policy)`, which would credit the incumbent; cost from the replay run; `family` forced to the source example's, so `temporal_splits` (`dataset.rs:617-672`) keeps both arms in one split (SPEC §17: "Group task families and duplicate replays together").
- `DATASET_VERSION` 5 → 6 with its doc paragraph (`:40-49`). `LABEL_POLICY_VERSION` stays 3: `labelling_of` and the Verified-route rule are unchanged; a replay is labelled by the same rule from its own evidence, and the new evidence source is recorded by `origin` and the dataset version.
- **The counterfactual gap.** `Dataset` gains `#[serde(default)] counterfactual_gap: { tasks, estimate: Option<MicroUsd>, basis }`: accepted live examples at implementation or escalation tier with no example one tier cheaper for the same task; the estimate is `tasks × mean complete cost` of cost-complete examples at the cheaper tier, `None` ("unknown, no priced observation") when there are none, never zero. `EvalReport` gains `#[serde(default)] examples_by_origin` and `counterfactual_gap` (`train_and_evaluate` has the dataset), so `relais report` reads them from the latest cycle's artifact JSON without a ledger step. Report lines, each ≤ 80 columns, never an action: `counterfactual gap: 14 accepted tasks lack a cheaper arm` then `  to fill it: relais dataset replay (estimated cost ~$3.20)`; with no priced observation the second line reads `cost unknown`, never `$0`.
- **SPEC.** One sentence each in §17 (after `:496`) and §24 (after `:826`): a settled replay arm enters `relais dataset build` as its own example, origin `replay`, in its source task's family; the replay command still compares, scores, ranks and promotes nothing.
- **Tests** (`dataset.rs`, `LedgerFixture` pattern at `:~800+`): *a replay does not supersede its accepted source* (both present, origins Live and Replay, same family); *a replay example carries its own tier, identity, recipe and cost*; *an errored or unsettled replay is excluded with a reason*; *a replay whose trial row has no `arm_run_id` (pre-v17) is excluded by name and its source still yields an example*; *a reverted source does not relabel its replay*; *a replay of a superseded source is excluded*; *old examples without origin read as live*; *the counterfactual gap counts tasks without a cheaper arm and prices unknown as unknown*; *temporal splits keep source and replay together*.

## Phase 3: the floor sweep (Rust, `learn/evaluate.rs`, `learn/summary.rs`) — done

- `measure` (`evaluate.rs:846-937`): split the per-record selection into `estimates_for(record) -> (candidates, Estimates)` computed once, then `select_learned` at each floor of `FLOOR_GRID` (integer hundredths `(50..=95).step_by(5)`, divided by 100) plus `inputs.quality_floor`, deduplicated on `(floor * 100.0).round() as i64` and sorted with `f64::total_cmp`. The gate path still uses `inputs.quality_floor` only (SPEC §17: a cheaper policy that fails the quality requirement cannot pass promotion). Abstention and `test_records` count tasks, not records: a source and its replay make one selection and one abstention unit, so replay examples do not move `abstention_rate` (test: *a source and its replay count one abstention*). The gate's `test_records`, `supported_test_records` and `abstention_rate` (`evaluate.rs:241-262`) all count tasks from 0.16.0; this changes the gate's unit, numerically identical while no replay example exists, and the CHANGELOG says so.
- `SweepPoint { floor, configured: bool, supported_test_records, acceptance_rate: Option<f64>, mean_cost_micros: Option<i64>, abstention_rate }`; `EvalReport.floor_sweep: Vec<SweepPoint>` with `#[serde(default)]`, carried by `Measured`; one line per point in `EvalReport::render` (`:1000`), the configured floor named `(configured)`.
- **No `EVAL_SCHEMA_VERSION` bump.** `Registry::evaluated` (`learn/registry.rs:377-397`) refuses a report whose version differs from the current one; a bump would strand a version-4 artifact `awaiting_promotion` until the next cycle retrains it. `by_label_source` (`evaluate.rs:314-316`) set the precedent: serde default, no bump; the sweep adds nothing to the gate, and the task-level counting above leaves every gate number unchanged on a dataset without replay examples.
- `LearningReport` (`summary.rs:44`) gains `floor_sweep`, `examples_by_origin`, `counterfactual_gap`; `learning_report` (`:63`) loads the latest cycle's artifact (`registry.load(artifact_id).evaluation`, lenient JSON, never `evaluated()`, which refuses failed gates; dataset and artifact files are written to a temp file and renamed, so a SIGTERM leaves nothing partial; a missing or unreadable artifact prints `floor sweep: unavailable (reason)` on stdout, exits 0, and is `null` in `--json`). Rendering: at most 5 sweep rows (the configured floor and its two neighbours each side), e.g. `    floor 0.75 configured  accepted 82%  abstain 31%  $0.42/task  n=25` (the configured floor is named in the row, never marked by a symbol alone; the width test uses worst-case values: `abstain 100%`, `$123.45/task`, 5-digit n), then `examples by origin: live N, replay M` and the gap line; `relais report --json` follows from `Serialize`. Report lines go to stdout, plain ASCII with no colour (none when piped or under `NO_COLOR`); diagnostics go to stderr. When the artifact is missing or predates these fields, the text report prints `floor sweep: not in this artifact; run relais learn cycle` and `--json` emits `null`, never an empty list.
- `learn/fixtures.rs:63` gains the new fields in its full literal.
- **Tests.** *abstention never falls as the floor rises* (the feasible set only shrinks; do not assert cost or acceptance monotonic: both are measured on supported records only); *the configured floor is in the sweep and matches the gate numbers* (its abstention equals `report.abstention_rate`); *a report without floor_sweep still parses* (version-4 JSON); `registry.rs`: a stored version-4 artifact still passes `evaluated()`; `summary.rs`: `every_row_stays_within_80_columns` (`:323`) extended with sweep, origin and gap rows, plus *the sweep shows at most five rows with the configured floor marked*.

## Not in scope

- Any Laya code, model or service. Laya enters the shipped product only through learning-loop Phase 8 or orchestrator-decides 4b/4c and their ADRs (SPEC §16).
- Changing the capability table, the research rule, or how a new task is raised to the session's tier (`router.ts:639-641`): the person's `/model` is respected; only a draw may go below it.
- Raising `epsilon_max` above the 0.1 envelope, or a separate spawn epsilon.
- Scheduling replays. The report names the gap and its price; `relais dataset replay` stays a person's command (SPEC §24).
- Soft (fractional) labels in the logistic learner: with one verified outcome per arm the per-arm hard label carries the information; a soft label needs sampled pairs relais does not have.
- Salvaging code from `microsoft/best-route-llm`.
- Subagent outcome attribution beyond what exists (own checks, parent amend). Review-type subagents have no verifiable outcome by nature; their draws will mostly read `unknown`, and the report says so per stratum.

## Decision log

- **D1** Exploration draws extend to subagent spawns inside the same 0.1 envelope; learning-loop D6 is reversed (person, 2026-10-11).
- **D2** The Laya amendments are decision-log entries in the two plans; SPEC §16 is not amended for them (person, 2026-10-11). The SPEC edits in Phases 1 and 2 state behaviour this plan changes (§30 exploration, §17/§24 replay examples) and are not covered by D2.
- **D3** Nothing is salvaged from `microsoft/best-route-llm`; its two ideas become Phases 2 and 3 on relais's own outcomes, in Rust.
- **D4** A replay run is an arm observation of its task, never a later attempt at it; the source run keeps its example; errored replays stay excluded.
- **D5** The quality floor stays a gate at the configured value; the sweep is a report. A floor change is a person's config edit.
