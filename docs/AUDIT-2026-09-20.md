# Relais audit — 2026-09-20

Scope: the whole crate at `1dbe8fe` (main after PR #3), read against
`docs/SPEC.md`, plus two live runs against the installed Claude Code
2.1.278 on this workstation. Four independent read-throughs (runner and
adapter; admission and coordinator; workspace, verify and scheduler;
contract, policy, route, context, ledger, learn, install) were merged and
every finding below was re-traced in the source or reproduced on the
command line before it was kept. Line numbers refer to `1dbe8fe`.

Baseline: `make check` is green — clippy clean, 194 unit tests, 9 release
scenarios, the 1.88 floor builds.

## Live-run evidence

Two runs on this repository, policy from `relais init` (verification
`make check`, 300 s), trust grant recorded by hand in `machine.toml`.

**Run 1, `inspect`, haiku** — `accepted`, $0.138 actual, 5 min 24 s wall.
The receipt binds run, candidate, base, contract hash and policy hash;
the coordinator started lazily, admitted one dispatch, settled the usage.
Two problems visible from the artifacts alone:

- The worker's answer — the whole deliverable of an inspect task — is
  stored nowhere. The run directory holds an empty patch, the check
  logs and the receipt; the ledger holds no result text. §4 says
  "inspection requires evidence criteria instead of a patch", and that
  evidence is discarded.
- The full verification profile ran twice (baseline and candidate) on
  an identical tree: five minutes of `make check` to verify that
  nothing changed. Candidate tree == base tree is knowable before
  spawning a single command.

**Run 2, `change`, fable + review** — `blocked (env_missing)`, $2.09
actual, one attempt. The contract asked for the adapter's own
budget-flag fix, scoped to `crates/relais/src/adapter/**`. The worker
was launched with no allow rules (argv observed:
`-p --model fable --effort medium --output-format json` plus five
`--disallowed-tools`), was refused every write, probed Edit, Write and
Bash for several turns, and then correctly answered with the
`relais-blocked:` protocol. The runner assigned `blocked`, bought no
stronger model and preserved the worktree. The right terminal state,
reached the expensive way: the result JSON's `permission_denials`
said the same thing after the first refusal, and a machine-owned
allowlist would have let the task proceed.

**Print-mode probes** (`claude -p`, haiku, a scratch repository):

- With no allow rules, a worker asked to edit one file returns
  `permission_denials: [Edit …]`, an empty diff and prose asking for
  approval. Relais ignores `permission_denials`, substitutes an empty
  result, snapshots the empty tree and verifies it — a `change` run in
  a repository without project allow rules is accepted with no model
  work performed if the baseline is green.
- `--settings '{"permissions":{"allow":["Edit","Write"]}}'` lets the
  same worker edit, with no `--permission-mode` and no bypass flag.
  This is the explicit, machine-owned grant §8 asks for.
- The installed CLI has `--max-budget-usd <amount>`, not `--budget`,
  and has no `--max-turns` at all. The adapter probes for the wrong
  spellings, so the dollar ceiling is silently never passed and turn
  ceilings cannot be passed.
- The result JSON has no top-level `model`; the effective model is only
  under `modelUsage.<id>.canonicalModel`. The adapter falls back to the
  requested alias, so §6 substitution detection can never fire.
- Repeated `--disallowed-tools` flags accumulate (verified: two flags,
  both tools absent from the worker's tool list).

## Findings

Severity: **A** breaks correct operation on this machine today; **B**
lets a worker or a planner escape the acceptance boundary; **C**
coordinator robustness; **D** learning, reporting, install; **E** dead
configuration and spec gaps. CONFIRMED unless marked PLAUSIBLE.

### A — correctness on the installed harness

- **A1. Harness failure is laundered into a completed attempt.**
  `adapter/claude.rs:174-178` turns non-JSON stdout into
  `result_text: Some("")`; the child's exit code is never consulted.
  An auth error, a rate limit, an unknown flag or `exit 1` becomes a
  normal attempt: the runner snapshots an empty candidate, runs the
  whole profile and, if the baseline is green, accepts. Fix: a non-zero
  exit or an unparsable result is `terminal_result_missing`
  (interrupted), never an empty terminal result.
- **A2. Permission denials are invisible.** `permission_denials` is not
  parsed; a worker that could not edit reports as a worker that chose
  not to. §8: missing permissions produce a `blocked` result. Fix:
  parse the array; any denial ends the attempt as
  `blocked:permission_denied` naming the tools.
- **A3. Workers get no permissions.** No allow rules are passed, and
  the user-level settings on this machine allow no file tools, so every
  `change` worker is denied `Edit`/`Write` (probe above). Fix: a
  machine-owned `permissions.allowed_tools` list passed via
  `--settings`, part of the machine authority; never a
  `--permission-mode`.
- **A4. Flag spellings.** `--budget` (adapter) vs `--max-budget-usd`
  (CLI, plain decimal); `--max-turns` absent on 2.1.278. Both are
  capability-probed by substring, and `--disallowed-tools` is the one
  flag pushed without a probe (`claude.rs:137-140`).
- **A5. Effective model never observed.** `parse_result_json` reads
  `model`/`actual_model`, neither of which exists; `modelUsage` does.
  Substitution detection (§6) and `models_used` in receipts record the
  alias that was requested.
- **A6. Candidate identity is not a content hash.**
  `workspace/mod.rs:156-178` calls `git commit-tree` with the ambient
  clock, so the same tree one second later has a different SHA. The
  §9 row "same failure and unchanged candidate → fail immediately"
  never fires; an idle worker buys a repair and a paid escalation. The
  unit test passes only because mock attempts finish inside one
  second. Fix: pin author/committer name, email and date on the
  plumbing call.
- **A7. Inspect deliverable discarded; identical tree re-verified.**
  See the live-run section. Fix: persist `result_text` as an evidence
  artifact for every attempt; skip candidate verification when the
  candidate tree equals the base tree and say so in the receipt.
- **A8. Unknown usage stored as zero.** `runner/mod.rs:912`, `:1464`
  `usage.cost.unwrap_or(ZERO)`; the sum reads as money. The
  completeness label does fold to `unknown`, which is what keeps this
  from being an A1-class lie, but §11 says never zero.
- **A9. Reviewer reads a patch that is never written.** The reviewer
  prompt names `candidate-latest.patch` (`runner/mod.rs:1329`); only
  `candidate-<n>.patch` exists. The reviewer also runs inside the
  worker's tree, where `CLAUDE.md`/`AGENTS.md` are not protected paths.
- **A10. Every `**` scope escalates.** The template's `**/trust/**`
  rule floors any scope that could reach a `trust/` directory, and
  `crates/relais/src/adapter/**` could. The live change run went to
  the escalation tier with mandatory review for a one-file adapter
  fix. The over-approximation is documented, but the template ships a
  rule that makes the cheap tiers unreachable for ordinary scopes.
- **A11. `relais report` panics on non-ASCII.** `report/mod.rs:146`
  slices at byte 120; the text is reviewer prose.
- **A12. Turn ceilings never applied.** `max_turns: None` at both
  dispatch sites; the CLI has no flag for it anyway. §11 promises a
  turn ceiling the product cannot deliver — say so in the capability
  report instead.

### B — acceptance boundary

- **B1. Scope is checked on the live tree, not the snapshot.**
  `changed_paths` (`workspace/mod.rs:136-148`) diffs the working tree
  and is called after the snapshot. A descendant that keeps writing,
  or a worker whose process group outlives the result, can add a file
  that is in the verified candidate but gone from the scope check.
  Fix: `git diff --name-only -z base..candidate`.
- **B2. Naming one protected prefix unlocks all of them.**
  `workspace/mod.rs:241-247`: a scope `[".claude/**"]` makes
  `relais.toml`, `amont.conf`, `.adr.yaml` and
  `.github/workflows/**` "explicitly allowed". Fix: tie the prefix to
  the path being judged.
- **B3. Non-ASCII paths defeat both checks.** git C-quotes them
  (`".claude/r\303\251glages.json"`), so `is_protected_path` sees a
  leading quote. Fix: `-z` and byte paths.
- **B4. `.gitignore` is an exit.** `add -A` and `--exclude-standard`
  both skip ignored files; `.gitignore` is not protected. A worker
  that appends a pattern hides its files from the diff, the scope
  check, the candidate and the exported patch while they remain in
  the retained worktree. Fix: protect `.gitignore`, `.git/info/exclude`
  and `CLAUDE.md`/`AGENTS.md`.
- **B5. Planner-chosen `package.id` is a filesystem path.**
  `scheduler.rs:535`, `:932`; `WorkPlan::validate` checks only
  non-empty and unique. With `"decomposition": "propose"` the ids are
  model output: `"../../.."` relocates the artifacts and the worktree.
  Fix: `[A-Za-z0-9_-]{1,64}`.
- **B6. Artifacts sit in the parent of the worker's cwd.** The worktree
  is `runs/<id>/worktree`; `receipt.json` is `runs/<id>/`. A worker
  with Bash writes `../receipt.json`, and `main.rs:861` prints that
  path as the receipt. The ledger copy stays honest.
- **B7. Deny list is a prefix match.** `Bash(git commit:*)` does not
  match `sh -c 'git push'`, `git -C . commit`, `env git commit`. Deny
  `Bash(git:*)` or allowlist.
- **B8. Verification-input edits go to a model, not to the user.**
  `runner/mod.rs:1045-1057` makes a candidate that edits `Cargo.toml`,
  lockfiles or the test tree review-required; §9 says `needs_decision`.
  Acceptance then hinges on `findings: none` in the last five lines of
  model text (`:1482-1493`). Kept as review because §10 also invites
  new regression tests, but the string test is the weak point.
- **B9. Environment inherited wholesale.** `claude.rs:142-146` removes
  one variable; `RELAIS_STATE_DIR`/`RELAIS_CONFIG_DIR` reach the worker,
  which can point a nested `relais` at its own `machine.toml`.
- **B10. amont bypasses and downgrades cannot block.**
  `verify/mod.rs:70-72` ignores them in `accepted()`; gaps are computed
  only for the check ids the profile enumerates (`runner/mod.rs:1288`).
- **B11. Fail-open guards.** `runner/mod.rs:492` skips the dirty-base
  refusal when `git status` errors; `workspace/mod.rs:268` runs
  `worktree remove --force` when the status check errors.
- **B12. Trust grants ignore recipes.** `policy/mod.rs:279-289` hashes
  everything but `recipes`, which pick a tier ahead of the learner.
- **B13. `recipe_covers` tests overlap, not containment**
  (`route/mod.rs:201-218`): a `**` contract is "fully covered" by a
  `docs/**` recipe.
- **B14. Reviewer tier.** `review_candidate` always picks
  `Tier::Escalation`; on an escalated run the reviewer is the model
  that wrote the candidate.
- **B15. PLAUSIBLE.** No `GIT_DIR`/`GIT_INDEX_FILE`/`GIT_WORK_TREE`
  sanitising; candidate commits are dangling objects a `git gc` can
  drop; `release_worktree` has no caller so `git worktree list`
  accumulates one entry per attempt and verification.

### C — coordinator

- **C1. Idle-exit kills in-flight runs.** `is_idle()`
  (`admission/mod.rs:899`) ignores registered runs; after 600 s with
  no running dispatch the daemon unlinks socket and lock and exits.
  A run spends minutes in verification between dispatches;
  `RemoteGate` never re-elects, so the next `admit` is
  `blocked:admission_unavailable` or `UnknownRun`. On this repository
  `make check` is under the limit only because the machine is fast.
- **C2. Pid-less leases leak forever.** `reconcile` frees a lease only
  in the `Some(pid) if !alive` arm; `launched` ledger rows with no pid
  are re-adopted at every start and never freed. Three killed runs
  take half the seats permanently.
- **C3. Self-reported depth, session and reservation are trusted.**
  `check_hard_limits` uses `request.depth`, not the parent's recorded
  depth; `reserve_micros: 0` or `i64::MAX` (wraps in release, panics
  and poisons the mutex in debug) evades the budget. `depth_of` exists
  and is unused.
- **C4. Unbounded read, unbounded threads.** `read_line` with a
  per-read timeout and a thread per connection.
- **C5. Cancellation never frees the seat.** `acknowledge_cancel` is
  unreachable from the wire; reconcile re-SIGTERMs the same pid every
  15 s, to `pid` not `-pid`, with no SIGKILL escalation.
- **C6. Liveness is `kill(pid, 0) == 0`.** EPERM reads as dead; a
  recycled pid reads as alive and becomes a SIGTERM target. `Bind` takes
  any pid from any client.
- **C7. Election is a pid in a file.** `create_new` makes the first
  creation atomic, but after a SIGKILL a recycled pid wedges every
  `relais run` until the file is deleted by hand. Hold an `flock`.
- **C8. Dispatch-id idempotency lapses after settlement**
  (`forget_if_settled`); `mark_waiting` is an unverified self-report.
- **C9. Tests.** Every "simultaneous" test is sequential calls on the
  state machine; nothing drives the socket from two threads. Parentage,
  depth caps and the waiting-parent protocol have no production caller
  (`managed_launch` always passes depth 0, parent `None`). No write
  leases exist, so "verification waits for write leases" is untestable.

### D — learning, reporting, install

- **D1. Artifact dimensions unchecked** (`registry.rs:65-89`): an
  8-weight artifact predicts over a 300-dimension space with no
  abstention.
- **D2. Temporal split leaks** (`dataset.rs:231-238`): a family pinned
  to train absorbs post-cutoff records.
- **D3. Calibration reported in-sample** (`evaluate.rs:160-184`).
- **D4. Cost model's cohort fallback unreachable; cost clamps near
  $485** (`learner.rs:253-268`); cohort is always `"change"`.
- **D5. `select_learned` treats a missing cost estimate as cheapest**
  (`route/mod.rs:403`, `None < Some`).
- **D6. `seed` is recorded and unused**; `fits_are_seed_reproducible`
  tests a deterministic function.
- **D7. Install cannot upgrade its own files** ("unchanged" is
  byte-equality with the *current* template, the marker sha is never
  checked), an Update rewrites the whole file, and a reordered marker
  pair panics the preview.
- **D8. Ledger reads `.expect()` on stored rows**; a newer ledger
  aborts `status`/`explain`/`report`; `main.rs` has nine more.
- **D9. Inclusive-total guard is inert.** `inclusive: false` is
  hardcoded and `parent_event_id` is always `None`, while Claude Code's
  `total_cost_usd` includes subagents.
- **D10. Prompt splices corpus text as instructions.** aval choices,
  objectives and planner package objectives enter the prompt as bare
  bullets; a newline in a constraint breaks the framing. §16 calls
  this text untrusted data.

### E — dead configuration and spec gaps

- `per_day_micros`: one occurrence in the crate.
- `[trials]` envelope: read nowhere; no replay command, no logged
  propensity, so §17's comparative evidence has no mechanism.
- `DEFAULT_CONTEXT_BUDGET_BYTES` is not configurable and counts only
  constraints.
- `doctor` ignores `[integrations]` modes.
- `aval resolve <key>` without `--`.
- `RELAIS_CONFIG_DIR`/`RELAIS_STATE_DIR` relocate machine authority;
  `HOME` unset panics.
- Reviewer dispatch is not spend-gated (`runner/mod.rs:1130` after the
  loop-top check).
- Prompt says "`max_attempts` command(s) judge the result"
  (`runner/mod.rs:1534`).
- `release_scenarios.rs`: the §14 interrupted-resume scenario is only
  exercised on an already-terminal run; the "cannot obtain acceptance
  by … modifying policy or changing files after verification" claim
  covers neither; the closing "no candidate patch" assertion is
  satisfied by every blocked path.

## Done well

- `runner::machine::decide` is the §9 table as a pure total function
  with a test per row; blocked never buys a stronger tier.
- Strict launch never degrades: no coordinator means
  `blocked:admission_unavailable` with nothing launched.
- One shared `wait_for_exit` kills the whole process group, for
  workers and for verification commands alike.
- Dispatch intent is written before spawn; `AlreadyAdmitted` stops a
  duplicate agent.
- Verification runs in a throwaway worktree at the candidate SHA;
  check labels are argv hashes, so baseline/candidate pairing survives
  reordering; baseline failures are never waived; missing amont
  inventory makes every required check a gap.
- Every SQL statement is a static literal with bound parameters; WAL
  with a busy timeout; additive numbered migrations with a real
  v1→v2 test.
- Integer micro-USD with one float boundary and saturating
  arithmetic; `Unknown` completeness poisons a total instead of
  zeroing it.
- `deny_unknown_fields` on every nested contract and policy struct.
- Policy is loaded once from the original checkout, never from the
  worker's worktree; `relais.toml`, `.claude/`, `.github/workflows/`
  are protected.
- No permission-bypass flag anywhere in the tree.
- Money reservation survives release until settle; unknown settles at
  the reservation as a lower bound with an `uncertain` counter.

## Disposition

Fixed in the PR that carries this document:

- A1, A2, A4, A5: the adapter probes `--max-budget-usd`,
  `--disallowed-tools` and `--settings`; a non-zero exit, `is_error`
  or unreadable output is a missing result (interrupted, with the
  stderr excerpt as evidence); `permission_denials` ends the attempt
  `blocked:permission_denied` with no escalation; the effective model
  is read from `modelUsage` and an alias is satisfied by the dated ID
  it resolves to; a session with subagents marks its usage inclusive.
- A3: `machine.toml` `[permissions] allowed_tools = [...]` reaches the
  worker as `--settings {"permissions":{"allow":[...]}}` — explicit,
  machine-owned, no permission mode. Reviewer and planner get none.
- A6: the snapshot pins author, committer and dates; identical content
  is an identical candidate, one second later or not.
- A7: the worker's answer is `attempt-<n>-result.txt` plus a
  `worker_result` evidence row; a candidate carrying the base tree
  reuses the baseline's check outcomes (transition
  `candidate_identical_to_base`) and, for a `change`, is the failure
  `empty_candidate` — repairable once, then the unchanged-candidate
  rule fails it.
- A9: `candidate-latest.patch` is written; the review is an evidence
  row. A10: the template's `**/trust/**` rule is a commented example.
  A11: char-boundary truncation. B9: the worker's environment loses
  `RELAIS_CONFIG_DIR`/`RELAIS_STATE_DIR`.
- B1–B3: scope and verification-input checks read the candidate
  commit (`diff --name-only -z base candidate`), never the live tree;
  a protected prefix is unlocked only by a pattern naming that prefix.
  B4: `.gitignore`, `CLAUDE.md`, `AGENTS.md` are protected. B5:
  package ids are `[A-Za-z0-9][A-Za-z0-9_-]{0,63}`. B11 (worktree
  half): a failing status check keeps the worktree. B12: recipes are
  in the authority hash.
- C1: idle-exit waits for registered runs. C3: saturating arithmetic,
  negative reservations refused, depth derived from the parent,
  poisoned-lock recovery. C4: requests are capped at 64 KiB.
- E: `aval resolve` refuses a key beginning with `-` before spawning
  (aval 1.5.0 rejects `--` itself, so the separator is not an option).
  Also, the runner now tells the coordinator when a run ends
  (`finish_run`), which is what lets the daemon idle-exit at all now
  that C1 makes it wait for runs.

Deferred, tracked as issues on the repository: A8, A12, B6, B7, B8,
B10, B11 (dirty-base half), B13–B15, C2, C5–C9, D1–D10, the rest of
E. The two live runs' artifacts are under
`~/.local/state/relais/runs/` on the workstation that ran them.
